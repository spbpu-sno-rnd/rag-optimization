# Контракт данных ingestion и retrieval

Контракт первой версии между сервисами подготовки данных и поиска.

## JSONL с чанками

Сервис ingestion записывает по одному чанку в строке JSONL. Для каждого чанка он создаёт UUID и использует его как ID точки Qdrant, значение `chunk_id` в payload и `Chunk.id` в Neo4j. Эмбеддинги также вычисляет ingestion; исходным документам не нужны ID чанков или векторы модели.

```json
{"chunk_id":"b3c2d56e-ae8e-44d3-bc44-a2d75a2ecb54","document_id":"report-2023","source":"report-2023.pdf","title":"Annual report 2023","text":"Компания Acme объявила ...","chunk_index":0,"metadata":{"author":"Research team","year":"2023","topic":"finance"}}
{"chunk_id":"26fb1d10-6c11-4f84-923d-838e8c143afa","document_id":"report-2023","source":"report-2023.pdf","title":"Annual report 2023","text":"Отношения с поставщиком ...","chunk_index":1,"metadata":{"author":"Research team","year":"2023","topic":"finance"}}
```

Обязательные поля: `chunk_id`, `document_id`, `text` и `chunk_index`. Поля `source` и `title` необязательны. Payload в Qdrant содержит `chunk_id`, `document_id`, `text` и `metadata`. Значения в `metadata` должны быть строками; по возможности включайте источник и позицию чанка.

## Qdrant

- Имя коллекции по умолчанию — `documents`; оно задаётся через `QDRANT_COLLECTION`.
- Сервис ingestion создаёт коллекцию с метрикой cosine и векторами размерности 384 от `intfloat/multilingual-e5-small`.
- Payload каждой точки содержит `chunk_id`, `document_id`, `text` и `metadata`.
- ID точки Qdrant и `chunk_id` в payload должны совпадать с ID соответствующего `Chunk.id` в Neo4j.
- Retrieval не создаёт коллекцию и не выполняет миграции; при запуске он проверяет, что настроенная коллекция существует.

## Neo4j

Адаптер Graph Local первой версии ожидает следующий минимальный граф:

- `(:Entity {name: string})`
- `(:Chunk {id: string, text: string})`
- `(:Document {id: string})`
- `(entity:Entity)-[:RELATED_TO]-(other:Entity)`
- `(entity:Entity)-[:MENTIONED_IN]->(chunk:Chunk)`
- `(document:Document)-[:HAS_CHUNK]->(chunk:Chunk)`

У связи `RELATED_TO` есть свойство `relation_type` и список `source_chunk_ids` с ID чанков, подтверждающих эту связь. В `Entity.name` хранятся канонические имена. Ingestion сопоставляет известные псевдонимы, но не объединяет автоматически неоднозначные названия.

Адаптер сопоставляет извлечённые имена сущностей без учёта регистра и обходит связи `RELATED_TO` на запрошенную глубину 1 или 2. Он возвращает структурированные факты из пройденных связей и тексты только тех чанков, чьи ID перечислены в `source_chunk_ids`. Чанки, где просто упоминаются соседние сущности, не используются как графовые доказательства. Направление факта соответствует направлению сохранённой связи. При настройке ingestion добавьте ограничения уникальности для `Chunk.id` и `Document.id`.

В первой версии изменение документов требует полной пересборки обоих индексов при остановленном поиске. Retrieval не обновляет индексы инкрементально.

## API обработки запроса

Retrieval вызывает `POST /v1/query-context` на `INGESTION_URL`:

```json
{"query":"How did Acme's 2023 launch affect its supplier?"}
```

Ingestion возвращает оба результата обработки запроса:

- `embedding` — массив ровно из 384 чисел от `intfloat/multilingual-e5-small` с префиксом `query: `;
- `entities` — массив канонических имён, совпадающих с `Entity.name`; если сущности не найдены, массив может быть пустым.

Для чанков используется та же версия модели с префиксом `passage: `. Некорректный запрос возвращает `400`, ошибка эмбеддинга или извлечения сущностей — `503` с описанием. В локальной первой версии авторизация не требуется.

Этот вызов выполняется для каждого поискового запроса. В гибридном режиме после него векторный и графовый поиск запускаются параллельно.

## Локальные хранилища

Скопируйте `.env.example` в `.env` и запустите базы:

```powershell
Copy-Item .env.example .env
docker compose up -d
```

Данные учётной записи Neo4j в примере предназначены только для локальной разработки. Docker Compose читает `.env`, но Go-сервисы не загружают этот файл автоматически. При локальном запуске Go-сервера задайте `NEO4J_PASSWORD` в окружении процесса.

При запуске retrieval проверяет Qdrant и Neo4j и записывает предупреждение, если одна из баз недоступна, но всё равно запускается. Поэтому гибридный запрос может вернуть частичный результат от доступного источника. `GET /healthz` проверяет только доступность HTTP-процесса; для проверки зависимостей смотрите статусы источников в ответе поиска.
